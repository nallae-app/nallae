# 날래 디자인 업그레이드 요청서 (Claude → Codex)

> 2026-10-21. 먼저 [AGENTS.md](../../AGENTS.md)를 읽을 것. 이 문서는 "무엇을, 왜, 어떤 제약 안에서"를 정한다. 세부 해법은 Codex가 제안하고 단계별로 구현한다.

## 0. 목표 한 줄
**"지금 우리 동네에 무슨 일?"에 3초 안에 답하는 지도.** 매일 열고 싶고, 긴급할 때 믿을 수 있는 앱의 완성도로 끌어올린다.

### 0-1. 사용자(제품 주인)의 평가 — 최우선 과제
> "지금 디자인은 솔직히 안 예쁘다. 너무 개발자 마인드의 디자인이다."

동의한다. 지금 화면은 '기능을 배치한 결과'이지 '디자인한 결과'가 아니다. 남색 배경 + 노란 포인트 + 시스템 폰트 + 테두리 박스 카드 = 흔한 대시보드 템플릿 인상이다. 사용성 개선(1절 이하)만으로는 부족하고 **아트 디렉션부터 다시 잡아야 한다.**
- 먼저 **무드와 레퍼런스**를 정한다: 날래가 어떤 감정이어야 하나(예: 차분한 신뢰 + 살아 있는 동네의 온기 + '날아온다'는 속도감). 토스·당근·애플 날씨·카카오맵 같은 국내외 소비자 앱 수준의 완성도를 기준선으로 삼는다.
- **지도 자체를 일러스트처럼**: 행정구역 면의 색·질감·경계선·바다·그림자를 '지도 데이터'가 아니라 '브랜드 화면'으로 다룬다. 지금의 짙은 남색 면 + 파란 선은 GIS 툴처럼 보인다.
- **타이포가 인상의 절반**: 한글 웹폰트(재배포 가능한 OFL, 예: Pretendard·SUIT 등)를 서브셋으로 내장하고, 굵기·크기 위계로 정보 구조를 만든다(테두리·박스로 나누지 말고).
- **박스와 테두리를 줄이고** 여백·면·그림자로 구분한다. 칩·버튼·카드 모서리, 아이콘 선 굵기, 그림자 체계를 통일한다.
- **움직임의 품질**: 위잉 펄스, 시트, 카드 등장에 이징·타이밍 체계를 둔다. 싸 보이는 애니메이션은 없느니만 못하다.
- 결과 판단 기준: "스크린샷만 보고 개인 개발자가 만든 앱인지 모르겠다."

## 1. 지금 화면의 문제 (실사용 데이터 기준 관찰)
1. **긴급도가 안 보인다.** 재난문자에는 `level`(위급재난/긴급재난/안전안내)이 있는데 화면에서 모두 같은 카드다. 강풍 예비특보와 화재가 같은 무게로 보인다.
2. **분류를 색으로만 구분한다.** 색각 이상·밝은 야외에서 구분이 안 된다. 아이콘·문자 보조가 없다.
3. **지도가 맥락이 없다.** 배경 지도·지명 라벨이 없어 확대하면 어디인지 모른다. 선택한 시·군·구 이름도 지도 위에 안 나온다.
4. **카드가 빽빽하다.** 재난문자 본문이 제목으로 잘려 들어가 첫 줄이 길고, 시간·장소·출처의 위계가 약하다. 펼친 상세에서 제목과 본문이 거의 중복된다.
5. **모바일 시트가 투박하다.** 손잡이를 '탭'해야만 접히고 끌어서 높이를 바꿀 수 없다. 스크롤과 지도 조작이 섞인다.
6. **최신성·상태 표시가 약하다.** "n분 전 업데이트"만 있고, 출처별 실패(`sources.*.ok=false`)나 수집 지연을 알 수 없다. 공식 알림이 아니라는 안내도 앱 안에서는 about 페이지에만 있다.
7. **첫 실행 안내가 없다.** 앱이 무엇인지, '내 주변'이 위치를 어떻게 쓰는지 설명 없이 바로 지도다.
8. **브랜드가 약하다.** 로고는 동심원뿐이고 시스템 폰트다. '날래'(빠르다·날아온다) 느낌이 화면에 없다.
9. **다크 테마 하나뿐.** 밝은 곳·밝은 테마 사용자를 고려하지 않았다.
10. **정책(목록 전용) 항목이 지도 항목과 섞여** 피드가 길어진다.

## 2. 지켜야 할 제약
- **빌드 도구·프레임워크 없이** 지금처럼 정적 HTML/CSS/JS. Leaflet·topojson-client는 `web/vendor/`에 내장된 것만.
- **런타임 외부 요청 금지**(CDN·외부 폰트·분석 도구 X). 개인정보처리방침에 "GitHub 외 외부 요청 없음"에 가깝게 적혀 있다. 폰트를 쓰려면 OFL 등 재배포 가능한 폰트를 서브셋해 `web/`에 넣는다(용량 예산 안에서).
- 기능 삭제 금지: 위잉(면 반짝임+펄스+말풍선), 첫 진입 1시간 재생, 내 주변(기기 안 판별), 시·도→시·군·구 확대, 분류 필터, 정책 항목 `onMap:false` 규칙, 데모 파라미터(`?demo`, `&near=`, `&open`, `&debug`).
- 접근성: 본문 대비 4.5:1 이상, 탭 대상 44px, 키보드 포커스 표시, `prefers-reduced-motion` 존중, 색 외 구분 수단.
- 성능: 앱 JS+CSS(데이터·vendor 제외) 100KB 이하, 저사양 안드로이드에서 지도 조작이 끊기지 않을 것.
- 문구: 해요체, 짧게. 재난을 오락처럼 연출하지 않는다(위급 소식은 차분하고 분명하게).
- 웹 코드를 바꾸면 `web/sw.js`의 `VERSION`을 올린다.

## 3. 원하는 결과물 (단계별, 각 단계는 독립적으로 배포 가능하게)
1. **디자인 토큰·타이포·아이콘 체계**: CSS 변수로 색(분류·긴급도·표면·글자)·간격·반경·그림자·모션을 정리. 분류별 SVG 아이콘(인라인). 라이트 테마(`prefers-color-scheme` + 수동 전환).
2. **소식 카드 재설계**: 긴급도 3단계(위급/긴급/안내·일반) 시각 위계, 분류 아이콘+라벨, 장소·시각·출처 위계, 상세 펼침(본문, 출처, 원문, 공유), 정책 항목은 '정책·관련' 묶음으로 접기.
3. **지도 맥락**: 시·도/시·군·구 이름 라벨(배율에 따라), 선택 지역 이름 표시, 범례(분류·긴급도), 위급 소식은 펄스를 차분하지만 분명하게.
4. **모바일 시트**: 끌어서 3단계 높이(접힘/중간/전체), 지도와 스크롤 충돌 해결, 데스크톱은 지금처럼 왼쪽 패널.
5. **상태·신뢰 표시**: 출처별 상태(정상/지연/오류)와 마지막 수집 시각, 새 소식 없음 상태, 오프라인 상태, "공식 재난 알림을 대체하지 않아요" 안내(과하지 않게 한 번).
6. **첫 실행 온보딩**: 2~3장, 건너뛰기 가능, 위치 권한은 '내 주변'을 누를 때만 묻고 이유를 먼저 설명.
7. **브랜드**: 로고/아이콘 개선안(동심원 모티프 유지 가능), 스토어 그래픽 이미지·스크린샷 캡션 시안.
