# Codex 진행 중 코드 검수

2026-10-22. 아직 구현 중이며 최종 판정 아님.

## medical.mjs 1차 검수
- parseXmlPage 오류에서 외부 errMsg/resultMsg를 그대로 Error.message로 쓰면 제공자가 요청 URL/키를 반사할 때 collect 로그에 유출될 수 있음. 원문 대신 허용된 코드/고정 문구만 출력할 것. fixture에 비밀 토큰이 든 오류 메시지를 넣어 출력 오류에 토큰이 없는지 검증.
- hhmmToMin의 48시 허용, 종료<=시작 시 24시간 덧셈은 근거 필요. 특히 0000/0000이나 같은 시간은 24시간 운영으로 단정하지 말고 미확인으로 두기. 2400 외 2600 같은 확장시간은 공식 근거 없으면 수용하지 않거나 원문 미확인 표시. 필터가 없다면 휴일/야간 판정 대신 보수적 시간표 표시만으로 충분.
- fetchEmergency 상세 호출이 개발계정 1,000건을 넘지 않는지 목록 총수/하루 재시도까지 예산 검토. 조회 실패 때 매10분 전체 재시도를 반복하지 않도록 실패 backoff 필요.
- 목록 페이징 총수 일치만으로 중복 페이지를 검출하지 못함. hpid 중복 페이지를 정상 전국 완전자료로 승인하지 않도록 중복 ID/페이지 totalCount 변화 검증 권장.
- 응급실 상세 응답 HPID와 요청 ID가 다른 경우 거부. unknown/invalid/지역미확정 누락은 서비스가 완전한 운영시설 전체라는 의미가 되지 않게 index 및 UI 설명 유지.

## app.js 1차 검수
- availableLayers가 pharmacyIndex/erData의 정상 자료 존재만으로 칩을 숨기면, 승인대기/전체실패 때 새 기능의 준비 상태와 재시도·119 안내로 들어갈 수 없다. 약국/응급실은 빈 정상자료와 실패/로딩/승인대기를 구분해서 진입 가능한 안내 화면 제공. 데이터 없을 때 실패가 시설 없음으로 표시되지 않아야 함.
- 응급실의 신규 갱신 lastFailure가 있어도 48h stale 전까지 상단 상태가 정상처럼 남는지 확인. 출처 설명을 열지 않아도 직전 정상 자료/갱신 실패임을 알 수 있게 표시.
- 지역별 약국 파일은 items 배열뿐 아니라 index의 updated/count와 일치하는지 검사. 배포 중/오프라인에서 서로 다른 세대 파일이면 완료/0곳 판정 대신 실패 또는 이전 자료 상태.
- 오늘 요일 강조가 공휴일 운영 확인과 혼동되지 않게 유지. phone 없는 항목에는 전화 미제공을 명시해 방문 전 확인 안내의 대안을 제공.
