## 수집 설계 (Codex 요청 반영)
- **perSggDaily 95% 재사용을 복제하지 않음.** 전국 갱신 인정 조건: 모든 쪽 성공 + 받은 행 = totalCount + 기관ID 중복 없음 + 쪽마다 totalCount 동일 + totalCount>0 + 직전보다 80% 미만으로 급감하지 않음. 하나라도 어긋나면 이번 결과 폐기.
- 폐기·실패 시 직전 정상 자료를 **모든 지역 파일이 개수까지 맞을 때만** 그대로 다시 쓰고 `lastFailure{at,error}`를 붙인다. 하나라도 못 받으면 `counts` 없는 실패 기록만 남긴다 → 앱은 '받지 못했어요'로 안내(0곳으로 보이지 않음).
- `counts`는 전국 완전 자료일 때만, 모든 시·군·구(0 포함)로 기록. 주소·좌표로 지역을 못 정한 곳(`unplaced`)·필수값 없음(`invalid`)·시간 표기 이상(`oddTimes`)·응급실 운영여부 미확인(`excluded.unknown`)은 개수를 남기고 출처 설명에 표시.
- 지역 배정: 주소(strict, 한 곳으로 풀릴 때) 우선, 없으면 좌표의 시·군·구. 둘이 다르면 주소를 따르고 좌표는 버림(지도 점 없음). 좌표 임의 생성 없음.
- 시간: 00:00~23:59와 24:00만 원문 그대로 보관. 2400 초과·시작=종료(0000/0000 포함)·한쪽만 있음은 '미확인'(null)으로. 종료<시작(예 2000-0200)은 원문 그대로 보여주고 다음 날로 해석하지 않음. 시간 없음은 휴무로 단정하지 않음.
- 호출 예산·backoff: 약국 성공 24h / 실패 3h(1회 약 50쪽 → 최악 하루 약 400건). 응급실 성공·실패 모두 24h, 상세 조회 상한 780건(넘으면 상세 호출 전에 실패). 간격 판단은 `updated`·`lastFailure.at`·`checkedAt`.
- 오류 문구: 제공자 원문(errMsg·resultMsg)을 쓰지 않고 숫자 코드+고정 문구만(키 반사 차단, 시험 있음). 요청 주소는 로그에 찍지 않는다.
- 산출물: `web/data/pharmacy/index.json` + `<시군구>.json`, `web/data/er.json`(전국 한 파일). 모두 git 제외, Actions 배포 때만 생성.

1. 공공데이터포털 로그인 → 두 페이지에서 **활용신청**(자동승인): https://www.data.go.kr/data/15000576/openapi.do , https://www.data.go.kr/data/15000563/openapi.do . 계정당 키 1개라 기존 `DATA_GO_KR_KEY` 그대로 쓴다(새 Secret 불필요).
2. 승인 반영 뒤 Actions → **probe-medical** → Run workflow. 출력의 '포털 오류 코드 20/30'이면 활용신청/키 반영 상태를 확인하고, `resultCode 00`이면 필드 목록으로 위 미확정 1·2를 확정한다.
3. 필드 확인 뒤 의료 출처만 대상으로 재수집하거나 기존 재시도 간격이 지난 다음 예약 실행에서 수집한다. 관련 없는 출처까지 강제 갱신하는 전체 force는 사용하지 않는다.
