# 디자인 1단계 구현 검토 메모

- 브랜치: `design/stage-1`. A·B는 색 토큰과 이름 옆 표식색만 다르며 DOM·구성·간격은 동일하다.
- 검토 URL: `?demo&design=A&theme=light`, `?demo&design=B&theme=dark`. 기존 `near`, `open`, `debug`를 함께 사용할 수 있다.
- 테마 버튼은 시스템 → 라이트 → 다크 순환. URL 지정은 해당 진입의 검토값이고 버튼 선택은 localStorage에 저장한다.
- 일반 신호는 brand, 나머지는 urgency에 대응하는 의미 토큰을 사용한다. 값 누락은 추정 없이 구분 미제공. 표시 근거는 상세에 원문 그대로 출력한다.
- 수집 파일 요청 실패, 출처별 수집 실패, 1시간 넘은 갱신 지연을 구별한다. 지연 기준은 화면 표시 기준이며 안전 판단이 아니다.
- 기본 피드 정책 묶음은 정책 필터로 연결된다. 기존 지역 선택의 지도 대상 제한(onMap:false 제외)은 유지했다.

## 대비와 용량

WCAG 상대휘도 공식으로 본문·보조 글자·brand·위급·긴급·미제공 색을 패널/보조 표면과 대조했다. 선택 칩(brand/selection-fill), 주 버튼(on-brand/brand), 지도 위 상단 글자(text 및 text-muted/sea)도 포함했다.

| 시안 | 테마 | 검사한 조합의 최저 대비 |
|---|---|---|
| A | 라이트 | 5.10:1 |
| A | 다크 | 5.37:1 |
| B | 라이트 | 4.88:1 |
| B | 다크 | 5.75:1 |

토큰 hex 보정 없음. 꿀색은 장식 표식에만 사용한다. 행정 경계는 문자나 조작부가 아닌 지도 구획선이다.
앱 JS+CSS는 37,216바이트(약 36.3KiB)(데이터·vendor·폰트 제외)로 100KB 이하. 서비스워커는 nallae-v3이며 폰트 CSS를 셸에 포함했다.

## 검증과 Claude 검토

- `node --check web/app.js`, `node --check web/sw.js` 및 기존 파서 시험 5개 통과.
- 임시 DOM 모의 시험: 초기화, urgency 누락/일반/위급, 제목 중복 판별, id별 DOM 재사용·수정·삭제, 보류 항목과 스크롤 보존, 열린 상세, 정책 접기, 빈 상태 확인. 프레임워크나 시험 의존성은 추가하지 않았다.
- 실제 브라우저 검증과 스크린샷은 수행하지 않았다. Claude가 375×812 A·B/라이트·다크/전국·지역 8장과 긴 제목·위급 배지를 검토한다.
- 특히 키보드로 상세를 연 뒤 수집 데이터 변경, 아래로 읽는 중 새 소식 버튼, 정책 묶음 포커스, 시스템 테마 실시간 변경, 재생 도중 테마 변경, 모션 축소에서 지도 비행·파문 생략을 확인한다.
- 모바일 하단 시트의 글자 확대/긴 지역명과 필터 가로 스크롤, 말풍선의 지도 가장자리 잘림, 실제 폰트 로드 및 오프라인 재진입은 실기기 확인이 남아 있다.
- 데모와 실데이터의 urgency/urgencyBasis 제공은 Claude 작업과 병합 후 확인한다. 필드가 없으면 모든 항목이 구분 미제공으로 표시된다.
