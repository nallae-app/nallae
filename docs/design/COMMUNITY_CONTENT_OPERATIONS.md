# 장소·코스 제보 운영 절차

기준일: 2026-10-25. 운영 연락처는 nallae.app@gmail.com, 공개 운영자명은 날래 개발자다. 공개 자료는 `web/data/community.json`에 운영자가 검토 후 추가한다. 빈 목록은 정상이며, 실제 제보 없이 후기·방문·평판을 만들지 않는다. 개인 별점과 메모는 기기에만 저장한다. 이를 제보나 공유 별점으로 전환하거나 사람 수·평균 평점으로 집계하지 않는다.

## 수신과 검토

1. 메일 앱을 열거나 초안을 저장한 것만으로 접수된 것으로 처리하지 않는다. 실제 수신한 메일만 처리한다. 수신 당시 공개 및 출처 상세 공개 동의, 방문 월, 제보 내용, 이해관계 선택을 확인한다. 누락이나 모호함이 있으면 보완 전까지 게시하지 않는다.
2. 개인정보, 타인 비방, 불법·유해 내용, 저작권 침해, 사적 주거지·제한 구역 위치를 제거하거나 반려한다. 제보자가 적은 내용과 운영자가 확인한 사실을 구분한다. 운영 검토는 방문 인증, 맛집 보증, 안전·영업 보증이 아니다.
3. 상호·공개 주소·공개 지도나 공식 출처를 대조한다. 출처의 사용 조건과 인용 가능 범위를 확인하고, 지도 핀을 실제 공개 장소 위치에 맞춘다. 제보자의 현재 위치, 이동 출발점, 집 주소를 좌표로 사용하지 않는다. 기존 장소의 이름이나 주소가 변경됐다면 이전 좌표를 재사용하지 않고 다시 확인한다.
4. `relationship`은 직접 선택한 `none`(관계·대가 없음), `owner`(운영자·관계자), `compensated`(대가 제공)를 보존한다. 누락을 `none`으로 간주하지 않는다. 관계·대가 내용을 숨겨 독립적인 추천으로 보이게 게시하지 않는다.
5. 초안의 `submitted-1` 같은 임시 장소 ID는 공개 전 안정적인 장소 ID로 교체한다. 기존 장소가 있으면 동일 ID를 사용하고, 동일 ID에 이름·주소·좌표가 충돌하지 않도록 한다. 코스의 순서가 바뀌면 별개의 v2 코스 ID가 된다.

## 공개

1. `schemaVersion: 1`, `items` 배열을 사용한다. 각 항목은 고유한 `id`, `kind`(place/course), `title`, `stops`, `recentVisit`, `reason`, `caution`, `relationship`, 두 공개 동의값을 가진다. 공개 장소마다 고유 ID, 이름, 주소, 확인한 숫자형 WGS84 위도·경도, 출처를 넣는다. 출처 URL은 자격증명 없는 http(s) 공개 링크만 허용한다. `referenceDate`와 `checkedAt`은 실제 확인한 과거 또는 당일 `YYYY-MM-DD`다.
2. 확인을 마친 항목에만 `status: "approved"`, `checked: true`를 부여한다. 코스는 순서 있는 2~4곳이며, 각 구간 직선거리 100~2,000m, 전체 직선거리 합계 4,000m 이하여야 한다. 실제 보행 경로나 소요시간으로 설명하지 않는다.
3. 발신자 이름·메일 주소·서명·전화번호·원문 메일·계정 정보는 공개 JSON, 문서, 커밋, 로그에 넣지 않는다. 원문을 그대로 복사하지 말고 공개 동의한 장소 정보만 옮긴다. `checked`는 운영 검토 여부이며 방문 인증이 아니다. 런타임은 `verification: "unverified"`로 처리한다.
4. `node scripts/check-community.mjs`를 실행한다. 실패하면 게시하지 않는다. 검사기는 스키마·승인·동의·좌표·중복 ID와 코스 저장 가능 조건을 확인하지만, 좌표의 실제 정확성이나 동의의 진정성을 대신 확인하지 못한다.
5. 웹 캐시 버전을 갱신하고 배포 후 실제 공개 화면에서 출처·관계 표시, 신고 동선, 장소 핀과 코스 순서를 확인한다. 공개 제보를 처음 추가하기 전에 아래 UGC 정책 요건을 충족했는지도 확인한다.

## 신고·공개 해제·삭제

앱의 콘텐츠 신고에서 해당 공개 항목 ID를 포함해 운영 메일로 접수한다. 개인 메일이나 원문을 공개 이슈에 붙이지 않는다. 개인정보 노출, 위험 위치, 권리 침해 등은 우선 공개 해제하고 확인한다. 수정 가능하면 재검토 후 게시하고, 동의 철회나 삭제 요청이면 해당 항목을 `items`에서 제거한다. 반복 악성 제보는 비공개 운영 절차로 수신 제한하고, 필요한 사용자·콘텐츠 차단 기능을 유지한다.

공개 해제 후 검사·배포하고 배포된 JSON에서 ID가 빠졌는지 확인한다. 제보 카탈로그는 네트워크 우선으로 갱신하여 오래된 승인 상태를 캐시가 계속 우선하지 않게 한다. 오프라인 기기나 이미 열린 화면, 외부 저장본까지 즉시 회수된다고 약속하지 않는다. 기존에 저장된 공개 코스도 최신 카탈로그에서 승인 해제된 항목을 계속 승인된 제보로 소개하지 않아야 한다. 공개 Git 기록에 민감정보가 들어간 경우 파일 수정만으로 해결됐다고 판단하지 말고 기록 제거와 노출 범위를 별도로 처리한다.

처리 완료 후 원본 메일과 첨부는 최대 90일 이내 삭제한다. 휴지통·다운로드한 첨부·작업용 복사본도 함께 정리한다. 공개 항목에는 필요한 장소·코스 정보만 유지한다. 공개 해제 판단과 처리 날짜 등 최소 운영 기록은 원문 및 개인 메일 주소와 분리하여 비공개로 관리한다.

## Google Play 사용자 제작 콘텐츠 정책

운영자가 사전 검토하여 정적 JSON에 게시해도 사용자 제보가 다른 이용자에게 보이면 UGC 의무가 자동 면제되는 것은 아니다. Google Play는 게시 전 약관/사용자 정책 수락, 금지 콘텐츠·행동의 정의, 지속적인 검토, 경험에 맞는 앱 내 신고·차단 및 조치를 요구한다. 공개 접근 UGC에 대한 사용자·콘텐츠 신고와 사용자 차단 요건도 검토해야 한다. 메일 접수와 사전 검토만으로 모든 요건을 충족한다고 주장하지 않는다. 실제 공개 기능과 작성자 식별·차단 설계에 맞춰 충족한 뒤 운영한다. 근거: [Google Play 사용자 제작 콘텐츠 정책](https://support.google.com/googleplay/android-developer/answer/9876937?hl=ko).
