# 지삐 설치 아이콘·헤더 삼단 검수 — 2026-11-07

사용자가 iPhone 홈 화면의 검은 테두리와 웹 헤더의 작은 크림색 상자를 지적했다. 사용자 요청에 따라 Codex, 독립 GPT 검토자, 실제 Claude가 수정 전·후 자료를 교차 검토했다.

실제 Claude 대화: https://claude.ai/chat/cc70d37f-b47e-4af6-81fd-2943f5a616ca

## 결함과 수정

- iOS가 참조하던 `icon-192.png`는 타일 본체까지 반투명이었다. 검은 배경에 합성하면 사용자 캡처와 유사한 테두리가 재현된다. 승인 그림 자체의 검은 선이라고 단정하지 않는다.
- 원본 색·글자·비율을 바꾸지 않고 설치용 PNG를 크림색(다크는 네이비)에 불투명 합성했다. 새 `apple-touch-icon-jippi-v1.png`는 180×180, 전픽셀 alpha255이며 별도 URL로 연결한다. 일반 PWA·maskable·Play 아이콘도 불투명 여부를 검사한다. 헤더·파비콘의 투명 심벌은 유지한다.
- 독립 GPT가 이전 아이콘을 지정 배경에 합성한 RGB와 수정본이 동일함을 확인했다. 원본 `approved-gpt.png`와 헤더 심벌 해시도 동일하다.
- 헤더에 배경색을 넣은 작은 카드에는 안쪽 여백이 없어 부제가 둥근 경계까지 붙어 잘려 보였다. 일반 데스크톱에서 실제 scrollWidth 넘침은 없었다. 카드 배경을 제거하고 헤더 전체를 글자 끝까지 불투명하게 보호하며 마지막 16px에서만 지도 쪽으로 사라지게 했다.
- 300px 이하의 기존 아이콘 전용 배치가 뒤쪽 모바일 CSS에 덮이던 문제도 고쳤다. 좁은 폭에서만 부제를 시각적으로 숨기고 버튼 이름은 보조기기에 유지한다.

## 논의와 반영

- 독립 GPT: iOS 불투명 전용 파일에 동의. 헤더에 padding을 더하면 320px 공간을 압박하므로 공통 보호 배경을 제안했다. 글자 뒤에서 gradient가 시작되면 중첩이 재발하므로 하단 16px에서만 전환하도록 조건을 제시했고 반영했다.
- Claude: 첨부한 iOS 합성 비교에서 검은 테두리 해소를 확인했다. 원본 타일의 경계·그림자가 희미하게 남는 점은 원본 보존 조건 아래 수용했다. 헤더 비교 실물에서도 작은 상자와 부제 잘림 인상이 해소됐고 차단급 시각 결함이 없다고 답했다.
- Android의 기존 컬러 전경은 승인된 타일 전체를 .46으로 넣어 작은 카드 안에 또 카드가 있는 인상이었다. 원·둥근 사각형·근사 squircle 합성에서 .46/.56/.64를 비교했다.
- 독립 GPT는 처음 안전 영역 검증 없는 확대를 반대했고, 중요 색상 픽셀이 안전 원 안에 들어옴을 계산한 뒤 .64의 판독성을 선호했다. Claude는 .64에서 장식 타일 모서리가 원형 경계에 밀착하는 점을 반대하고 .56을 권했다. 실제 런처를 확인하지 못한 상황에서 Codex는 컬러 .56을 선택했고 두 검토자가 수용했다.
- 단색은 다른 원본(글자 없는 핀·지도)이다. .56으로 키우면 alpha≥128 실루엣의 일부가 66dp 안전 원을 벗어나므로 .46을 유지한다. Claude의 .54 제안도 검토했으나 안전 여유가 작고, 현재 단색 실루엣이 컬러 핵심 그림보다 이미 커서 동일 배율을 목표로 삼지 않았다.

## 검증

- 전체 자동 시험 105개 통과. 추가한 아이콘 시험은 iOS 연결·180px 크기·불투명도, PWA/Play 불투명도·헤더 투명도, Android 핵심 그림·단색의 안전 원을 검사한다.
- Android 108dp=432px 기준 안전 원 반경132px. 색상·대비로 구분한 컬러 핵심 그림은 .56에서 라이트94.44px/다크97.95px 반경 안이다. 이 색상 분류는 장식 타일·약한 그림자를 제외한 보조 검사이며 이미지 의미를 완벽히 분리하는 판정은 아니다.
- 실제 브라우저에서 320/390/1366px × 라이트/다크 6조합을 캡처했다. 문서·부제 넘침0, 우측 버튼과 브랜드 겹침0, 글꼴 로딩 완료. 부제 하단64/66px까지 불투명 배경이 유지된다.
- 240/300px 축소 레이아웃에서 넘침·겹침 없음. 188px 요청은 도구에서 실제240px로 제한되어 188px 통과로 보고하지 않는다. 실제 OS 글자 확대 200%를 검증한 것은 아니다.
- Claude 최종 답변은 ‘차단급 반론은 없습니다’였고, 단색 원본·실루엣 크기를 설명한 뒤 .54 확대 제안을 철회했다. 추가 조건인 좁은 화면의 지도 버튼 터치 영역은 실제240px에서 두 버튼 모두44×44px로 확인했다.
- 비교 자료: `review-current/jippi-icons/ios-comparison.png`, `android-masks.png`, `header-comparison.png`.

## 한계와 설치 주의

- iPhone 홈 화면과 Android 런처의 실제 업데이트 확인은 남아 있다. 기존 iOS 설치 아이콘이 웹 배포만으로 자동 갱신된다고 보장하지 않는다.
- 저장 코스·개인 기록이 있는 기존 PWA를 무조건 삭제하도록 안내하지 않는다. 먼저 Safari의 새 홈 화면 추가 미리보기에서 새 아이콘을 확인하고 기존 기록 보존을 확인한다.
- Android 수정은 별도 AAB 업데이트가 필요하다. 웹 배포가 Android 런처를 바꾸는 것은 아니다. 패키지·업로드 키·저장 키는 유지한다.
- 라이트 헤더 하단 전환의 인상, 실제 OS 글자 확대, 원형·squircle 실제 런처의 표시를 브라우저·합성 검수와 구분한다.

## 배포·스토어 마감

- 웹 수정 커밋 `91c9c50`, Actions `42380795145` 성공. 공개 HTML·CSS·SW와180/192/512px 설치 PNG를 직접 받아 커밋과 일치함을 확인했다. 공개 설치 PNG는 전부 불투명이다. 기존 캐시 사용자는 첫 방문 후 새로고침이 필요할 수 있다.
- Android 후속 빌드1.0.2/code3은 Gradle 빌드·AAB/APK 서명 검증 성공. 원래 업로드 인증서와 일치한다. 패키지는 `app.nallae`, min24/target36 유지. Alpha에 업로드해 새 출시로 저장했다. 실제 설치와 Google 승인 완료를 의미하지 않는다.
- 스토어 휴대전화4장도 최신 공개 서비스에서360×640으로 다시 촬영했다. 첫 이미지 순서는 소개→코스→상세→다크로 한 장씩 업로드해 확인했다. 태블릿7·10인치 각2장과 데스크톱4장은1920×1080 실제 브라우저 캡처로 교체했다.
- 대표 배너는 확정 카피·로고·배치를 유지하고 새 코스/다크 캡처만 목업에 반영했다. 실제 Wanted Sans loaded 메타와 이미지 로딩·1024×500 크기를 확인했다. PNG와 SVG 예비본의 내장 PNG가 해시까지 일치한다.
- 독립 GPT가 뷰포트 전환 직후 찍힌 첫 다크 캡처의 지도 이탈·바다 위 지명을 발견해 반려했다. 독립 모바일 탭에서 실제360×640을 확인하고 전국 재정렬 후 재촬영했다. 이 새 파일과 이를 넣은 네이비 배너는 사후 검수 통과했다. 문제 파일을 최종 제출본으로 사용하지 않는다.
- Claude도 스토어 크림·네이비 배너와 모바일 실물을 첨부로 검토했다. 스크롤 중 화면 끝·헤더 아래 지도 마커 노출에 대한 비차단 반론을 기록했다. 독립 GPT는 최종 다크2장과 태블릿/PC4장의 지도·라벨·브랜드 배치를 추가 확인했다.
- 교체한 최종 다크2장을 Claude에게 다시 첨부했다. 최종 답변은 ‘놓친 차단 결함은 없다고 판정합니다’였으며, 문구 전체·프레임·지명 배치에 문제가 없음을 확인했다. 헤더와 시트 사이의 작은 마스코트 일부 노출만 비차단 의견으로 남겼다. 이 판단 역시 첨부 이미지 기준이다.
- 최종 스토어 변경5개와 Alpha1.0.2/code3을 합친6개 변경사항을 전송했다. 기존1.0.1 검토를 수정본으로 갱신하기 위해 Console의 검토 재시작을 진행했다. 이후 ‘검토 중인 변경사항’에1.0.2가 표시되고 Google 빠른 검사가 실행 중임을 확인했다. 검사 통과 후 검토되며 승인·설치 완료는 아니다. 증거는 Git 제외 `android/jippi-icons-20261107/store/play-final-submitted.png`.
